# 内测邀请码模块

目的：通过独立的临时入口控制内测访问，不改变 Google 登录、创建者身份或作品归属。没有通过验证时不挂载首页、编辑器或播放器。

## 配置

通用默认值位于 `Qingfeng_AI_Music/qf-server/src/main/resources/invite-gate.properties`，默认关闭，真实邀请码不进入 Git、JAR 或前端资源。

本机已随机生成独立的私有配置：`Qingfeng_AI_Music/config/invite-gate.local.properties`。该文件被现有 `.gitignore` 忽略，由 mysql、local 启动配置加载，兼容从工作区、后端根目录及 qf-server 目录启动。test 配置不读取它。

```properties
qingfeng.invite-gate.enabled=true
qingfeng.invite-gate.codes=<私下分发的邀请码，多个用逗号分隔>
qingfeng.invite-gate.signing-key=<随机生成的至少32字符签名密钥>
qingfeng.invite-gate.session-ttl=7d
qingfeng.invite-gate.attempts-per-minute=10
qingfeng.invite-gate.secure-cookie=false
```

修改配置后重启后端生效。启用时缺少合格的邀请码或签名密钥会拒绝启动，不会静默放行。

正式服务器可使用 `/etc/qingfeng-music/invite-gate.properties`，或设置环境变量 `INVITE_GATE_ENABLED`、`INVITE_GATE_CODES`、`INVITE_GATE_SIGNING_KEY`、`INVITE_GATE_SESSION_TTL`、`INVITE_GATE_ATTEMPTS_PER_MINUTE`、`INVITE_GATE_SECURE_COOKIE`。HTTPS 服务器设置 `secure-cookie=true`。私有配置优先于随包默认配置；不要同时在多个位置维护不同的邀请码。

## 使用行为

- 首次访问弹出中英文邀请码框，支持切换语言；不能通过 Escape 或点击背景跳过。
- 正确验证后以单独的 HttpOnly、SameSite=Lax Cookie 保存资格，默认有效期七天，同浏览器刷新不重复要求输入。不把邀请码放在 URL、localStorage 或 sessionStorage 中。
- 邀请验证不创建账号、不合并作品；Google 登录和作品找回仍按原规则执行。
- 错误邀请码不放行；服务不可用或返回损坏响应时保持关闭，提供重试入口。
- 服务端拦截尚未通过验证的 `/api/**` 和 `/media/**` 访问，包括直接访问公开礼物、找回、Google 登录和创作接口。静态界面、logo、健康检查以及邀请码自身接口允许加载，以便显示入口。
- Google 回调在缺少资格时跳回 `/account` 展示入口，不携带回调查询参数。支付 Webhook 是服务器通知，保留原签名校验，不要求交互邀请码。
- 提交邀请码受 CSRF 和按远端地址的次数限制保护；不直接信任浏览器提供的转发 IP 头。当前限流适用于单实例，可信反向代理转发应由服务器统一配置。
- 更新邀请码或签名密钥使旧资格失效。打开的页面遇到 `INVITE_REQUIRED` 会重新显示入口，并保留已挂载编辑器的内容，不自动重发失败请求，尤其不重发付费生成。
- 失效后的重新验证完成，只恢复页面访问；用户自行决定是否重试先前操作。
- 必须确保生产 `/api/`、受限媒体访问经由后端；独立静态主机、Vite 开发服务器直接提供的公开资源不经过 Java 过滤器。

## 关闭和删除

结束内测时先在实际加载的私有配置中设置：

```properties
qingfeng.invite-gate.enabled=false
```

重启后端后，新进入或刷新的页面将直接通过。已有弹窗切回窗口后会重新核对，也可点击“重新验证”。不需要重新构建前端，不影响账号和现有作品。

后续彻底移除时：

1. 从 `src/app/App.vue` 删除 `BetaAccessGate` 引入及外层包裹，保留原 layout/RouterView。
2. 删除前端 `src/modules/beta-access/`；从 `shared/http/api-client.ts` 删除 `qingfeng:invite-required` 通知。
3. 从 `WebSecurityConfiguration` 删除 InviteGateService 参数、过滤器注册及两个邀请码入口匹配。
4. 删除后端 `server/invite/`、对应测试、`invite-gate.properties` 及各 application 配置中的相关导入。
5. 删除私有邀请码文件及不再使用的翻译、测试。

无需数据库迁移，无需修改作品、身份或支付数据。

## 本地验证范围

验证涵盖签名伪造、过期、配置轮换、错误邀请码、CSRF、请求次数限制、Cookie 属性、关闭开关、跨浏览器隔离，以及真实 HTTP 安全链中邀请码与账号身份的独立性。浏览器验证使用隔离端口和 H2，不访问生产，不调用付费模型。
