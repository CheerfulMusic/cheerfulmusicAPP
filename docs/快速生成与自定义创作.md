# 快速生成与自定义创作

## 用户流程

`/create` 新建作品默认快速入口；已有作品默认自定义入口。`mode=quick/custom` 可指定入口。两个入口保留标题“从这一刻起，你也是歌手。”，共享故事、语言、音乐方向和本机恢复副本。

- 快速入口：创作描述、AI 改写、歌词语言、原有六个风格标签、一键生成音乐。没有独立的歌曲感觉选择区。普通风格标签不改动故事；只有空白时主动选择“我还没有灵感”才填入示例。
- 自定义入口：写词前选择曲风、情绪、节奏、演唱声音、歌词结构；乐器、唱法、编排和排除项折叠展示。先保存音乐方向再写词，编辑歌词后仍需点击保存，随后确认并谱曲。
- AI 推荐允许不指定曲风，根据故事与创作计划确定方向；没有明确要求时使用可访问的流行方向作为后备，不暗中固定为民谣。当前排除项与声音设置一并传入写词请求。
- 切换入口保留素材和设置；快速入口沿用已有自定义音乐设置时显示提示。写词后修改音乐方向，会提供保留歌词或打开调整要求的操作，打开面板不会自动付费生成。
- 手机端隐藏右侧装饰，自定义按钮在表单底部，避免固定操作栏遮挡选项；快速按钮保留小屏可达的操作栏。

## 后端推进

新增业务编排 `creation/QuickCreationService`、持久化端口 `QuickCreationRepository`、JDBC 实现和 `V28__quick_creation.sql`。复用原来的作品、写词、歌词确认、音乐预检、任务提交、额度、积分及音频归档，不另建音乐提供方或外部队列。

```text
QUEUED → WRITING → LYRICS_READY → SUBMITTING_MUSIC → MUSIC_QUEUED
                                                       ↓
                                  原音乐任务负责查询、归档、完成或失败
```

HTTP 创建接口只保存流程，立即返回；关闭网页不停止服务器后续推进。每条流程保存作品版本、写词请求键、音乐请求键、歌词版本及音乐任务，两个付费阶段使用不同的固定请求键。

`GET latest` 结合原音乐任务返回真实状态；“我的音乐”把排队、写词和准备音乐也列为制作中。作品删除后不再被编排器领取，不恢复已删除作品。

## 恢复边界

- 重复点击同一请求只产生一条流程。创建者与作品准入锁仅用于短事务，模型 HTTP 不占数据库事务。
- 默认 4 个独立写词/编排执行循环，可配置为 1—16；不会占住音乐查询和归档线程。音乐阶段继续使用现有并发限制和 KIE 共享速率门控。
- 写词请求仍在处理中时只查询；进程中断后用原请求键恢复，未确认前不重发模型请求。过期写词按现有 180 秒策略结束。
- 歌词成功而音乐准备失败时保留歌词，明确重试从音乐阶段继续，不新增歌词版本。
- 音乐任务已落库但回执丢失时查找原任务；音乐上游提交不明确、音频保存失败等继续交给原任务的查询和归档恢复机制，不在编排层重复购买。
- 全局/个人并发暂满且尚未发起该阶段付费调用时延后检查。额度耗尽、积分不足、模型调用失败等保留内容并提示用户处理，不无限重试。
- 流程采用 180 秒数据库租约和令牌条件更新，旧执行者不能覆盖新执行者检查点。
- 新流程按创建者约束待推进数量，防止连续建立多份一键任务。原音乐阶段的额度与积分校验仍在正式提交事务中执行；一键入口不承诺所有失败退款。

## 接口与开关

```text
POST /api/app/works/{work}/quick-creations
GET  /api/app/works/{work}/quick-creations/latest
GET  /api/app/works/{work}/quick-creations/{id}
POST /api/app/works/{work}/quick-creations/{id}/retry
```

以上接口沿用登录身份、作品归属检查和 CSRF 防护。没有流程时 `latest` 可为空；前端校验其他响应的必要字段及状态。

```properties
qingfeng.quick.enabled=true
qingfeng.quick.workers=4
```

快速入口能力还要求写词与音乐服务启用并已配置，以及 `qingfeng.generation.scheduler-enabled=true`。应用就绪后才启动编排执行器；关闭调度的日常本机主库入口不会启动它。关闭 `quick.enabled` 会暂停新入口及编排，已经进入原音乐任务的查询归档仍由原执行器负责。

## 本机查看新版页面

在日常入口已经运行时，可明确执行 `scripts/start-preview.ps1`。它核对 PID、启动时间和 5173 端口归属后，仅停止原前端，改为从工作区 `Qingfeng_AI_Music_VUE` 加载源码；登录后端、SSH 隧道和现有业务接口不变。运行记录标为 `frontend-preview`，分别记录后端版本和前端提交；停止仍使用 `scripts/stop-main.ps1`。

该入口用于查看开发中的页面，不表示新版业务后端已经上线。它不运行数据库迁移，不启动新的一键编排器，不提供虚假的可用能力。新后端未发布时，一键按钮会保持未开放。恢复线上同版日常入口应先停止当前入口，再执行 `scripts/start-main.ps1`，不要手动覆盖旧运行快照。
