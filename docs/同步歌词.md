# 歌曲播放同步歌词

作品页歌曲结果卡片采用「专辑封面 / 歌名与送礼 / 同步歌词」三列布局；窄屏改为上下排列。继续使用原有 Cheerful Music 黑色与橙红色品牌。当前句高亮、前后句淡化，随播放在歌词框内居中滚动，不推动整页。

## 行为

- 时间轴绑定归档音频 `assetId`，歌词正文取生成任务的快照，后续编辑歌词不会改变已生成歌曲的时间轴。
- 播放、暂停、拖动进度、点击歌词跳转共用全站播放器；播放别的歌曲时不高亮本页歌词。
- 前奏、间奏、尾奏不将尚未演唱的内容高亮；不使用平均时长或定时器伪造逐句时间。
- 手动滚动时暂停跟随 6 秒，也可点击「回到正在唱的歌词」立即跟随。支持键盘、减少动态效果设置和中英界面；用户歌词保持原文。
- 没有时间轴时显示完整歌词。可用的 KIE 生成音频可点击「同步歌词」获取一次；页面打开、刷新和播放仅读取缓存，不自动调用供应商。导入音频没有时间轴时仍显示选定歌词正文。

## 数据与接口

`GET /api/app/works/{work}/audio/{asset}/lyrics` 读取本人音频的时间轴；`POST .../lyrics/sync` 携带 `requestKey` 发起同步，受会话、CSRF、归属检查及额度控制保护。不会把供应商密钥、曲目编号或临时音频 URL 暴露给前端。

新增 Flyway V8 表 `media_lyrics_timeline` 保存原始有效时间片；按供应商换行/单词边界分句，句子的开始和结束时间均来自真实时间片。兼容逐词、逐句数据，移除 `[Verse]` 等段落标记。

同步时先通过 KIE 只读任务详情核对归档音频的具体版本，再获取该版本时间轴。接口模式由 `qingfeng.providers.kie.lyrics-timing-mode=compatible|unified` 选择，不自动切换接口，也不自动重发 POST：

- [KIE 官方兼容时间轴接口](https://docs.kie.ai/old-model/suno-api/get-timestamped-lyrics)：当前实测可用，默认 `compatible`。
- [KIE 统一时间轴接口](https://docs.kie.ai/suno-api/get-timestamped-lyrics)：支持通过配置切换，解析同步嵌套响应及 snake_case 时间字段。

## 缓存与额度

缓存状态：`NOT_REQUESTED / FETCHING / READY / EMPTY / FAILED / UNKNOWN`。同一音频并发请求只处理一次，成功后新请求键也直接复用缓存。明确失败后，只有用户主动重试才使用新键；网络超时和中断视为结果未知，刷新只查状态。中断的 FETCHING 超过 3 分钟转 UNKNOWN，不自动重发；维护人员需核对供应商记录后再处理未知状态。

同步额度独立于歌曲生成和 AI 歌词编写：默认个人 10 次/天、全站 100 次/天，个人同时 1 次、全站同时 5 次，按上海时间每日重置。实际为请求次数限制，不代表供应商收费金额。跨音频复用同一请求键也不能绕过计数。可在私有 `config/local.properties` 覆盖：

```properties
qingfeng.lyrics.timing.enabled=true
qingfeng.providers.kie.lyrics-timing-mode=compatible
qingfeng.usage.timing.daily-per-creator=10
qingfeng.usage.timing.daily-global=100
qingfeng.usage.timing.concurrent-per-creator=1
qingfeng.usage.timing.concurrent-global=5
```

0 表示禁止新请求；读取已有缓存不受生成开关影响。存储在数据库中，服务重启后继续使用。
