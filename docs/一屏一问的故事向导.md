# 一屏一问的故事向导

2026-11-03，本轮为本地前端优化，未部署，未调用真实付费模型。不修改后端接口、数据库结构或已有歌曲。

## 填写流程

故事部分分为四屏，每屏只展示当前问题：

1. 送给谁：称呼输入框和首批六个示例，可展开更多，也可自行填写。
2. 送歌时刻：自行输入或选择示例；新建作品不再默认恋爱纪念，增加「不为特别的日子」。从首页特定场景进入时仍尊重该场景。
3. 一段回忆：一个多行输入框。灵感标签只切换提问方向，不自动编造或覆盖经历；暂时想不起来可以先去写心意。
4. 一句心意：一个多行输入框。已有回忆时可跳过；没有回忆时留下一句真心话即可。仍沿用原来的「回忆或心意至少一项」规则，不额外强制填写两项。

四屏之后，单独选择中文、英文或中英混合，再明确点击生成歌词。歌词语言和网站界面语言相互独立；切换界面语言不修改已写内容。

生成后进入可编辑的歌词页，作品名称在此修改。「选择旋律与声音」入口放在歌词页，保存音乐设置不自动生成歌曲；用户再明确点击生成歌曲。已有作品的风格、声线和标题会保留。

## 交互与恢复

- 延续黑色背景、橙红主按钮；缩窄正文，突出当前问题与一条细进度线。
- 右侧改为简短提示和已填写的称呼、场景摘要，提供返回修改；手机隐藏侧栏，底部固定主要操作。
- 必填错误在当前问题附近显示，关联输入框的无障碍错误状态；多行输入正常换行，不用回车提交。
- 保留服务器自动保存、失败时的本机副本、冲突处理和刷新恢复。
- 问题地址使用 `question=recipient/occasion/story/message/language`；浏览器前进、后退保留答案和当前问题。
- 新建向导使用本机草稿标识维持同一次填写过程，自动保存不会改变之前历史条目的作品上下文。该标识不替代服务端的会话和作品归属校验。
- 本机恢复记录增加 `flowVersion=2`；旧三页记录的进度映射为称呼、回忆、语言页。原 `part=1` 的返回修改故事链接继续兼容。
- 再次从空白 `/create` 开始会创建新向导；原草稿仍可从「我的音乐」继续编辑。
