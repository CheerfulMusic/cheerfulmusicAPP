# 局部改词与版本对比

更新于2026-11-03。本轮只完成本地代码与离线验收，未部署；不改变线上发布 `20261103-06-usage-config`。未提交真实付费局部重唱请求。

## 用户怎么使用

1. 打开已生成歌曲，在歌词旁点「改词」，或点「局部改词」。上传的音频暂不支持此功能。
2. 选择要修改的完整歌词行，编辑新歌词，试听并确认重新演唱的开始、结束秒数。有真实缓存时间轴时，系统会建议范围，并带入范围内相邻歌词；没有时间轴时由用户试听定位，不伪造时间。
3. 点「生成修改版」。任务独立保存；提交给供应商前保留5秒撤销窗口，开始提交后不能承诺取消或退款。处理期间仍可听原曲。
4. 完成后分别点「听原版」「听修改版」循环对比片段，满意再点「使用这个版本」。试听本身不会修改当前使用版本。

供应商要求每次修改至少10秒、不超过原曲时长的一半，时间精度为0.01秒。因此修改一句也可能涉及附近几句，必须保留其中不需要改动的歌词。字数、节奏和断句接近原句通常更容易衔接。模型会参考原曲，但修改片段内的旋律、音色和唱腔可能变化，不能保证只换字且声音完全一致。

原版与历史音频不会覆盖。改词会形成独立歌词版本和生成任务；当前音频选择持久化，并做版本冲突检查。旧礼物分享固定保留当时的歌曲与歌词，不随作品当前选择变化。

修改版的歌词跟随其生成快照展示，不套用原曲旧时间轴。若需逐句同步，应针对修改版另行明确执行同步，可能涉及供应商费用。

## 实现边界

- 复用 KIE Suno `ai-music-api/replace-section`，以原供应商任务编号、音频编号、修改秒数、修改片段歌词及修改后完整歌词提交；保留原曲的标题、风格和声线参数。
- 歌曲生成查询同时登记音频编号、时长和对应资源。旧作品缺少这些信息时，只查询原平台任务并匹配已归档的音频；不能确定对应版本时不允许编辑，不猜测音频编号。
- 任务继续使用持久化队列、租约、结果查询及完整音频归档。已获取任务编号后只查询该任务；提交结果未知时不自动重提付费请求，不回退为整首重新生成。
- 浏览器短暂保留本次编辑草稿及未确认请求标识。相同请求重放绑定相同修改内容，后端事务去重；更改请求内容必须使用新的请求标识。
- 每次局部修改计入音乐创作额度，并发和每日额度继续统一读取 `config/usage-limits.properties`；只读查询、取消及选用音频不新占创作额度。
- 播放器共用完整音频缓存；A/B切换可复用两份已加载音频，循环试听不重复下载。大文件仍受既有缓存容量限制。
- 编辑、任务历史与版本选择均校验作品归属。修改版归档完成后才可选用。

## 配置与数据库

局部改词同时受以下开关控制；仍需后端已有可用的 KIE 私有密钥：

```properties
qingfeng.generation.enabled=true
qingfeng.generation.section-editing-enabled=true
qingfeng.providers.kie.section-audio-weight=0.85
```

`section-audio-weight` 取0至1，为参考原曲的初始调优参数，不能视为听感保证。关闭局部编辑开关不删除历史音频。

Flyway 新增 `V12__section_edits_and_audio_selection.sql`，增加生成音频源信息、修改任务描述及作品当前音频选择三张表，不重写原歌词、音频和分享快照。本地 IDEA 后端重启时自动迁移；无需手工执行SQL。本轮没有对生产库执行迁移。

新增接口（沿用匿名会话、CSRF及归属校验）：

| 方法 | 路径（以 `/api/app/works/{work}` 为前缀） | 用途 |
| --- | --- | --- |
| GET | `/audio/{asset}/section-context` | 原曲歌词、时长、已有时间轴与可编辑原因 |
| GET / POST | `/section-edits` | 修改历史 / 创建局部修改任务 |
| GET / PUT | `/audio/selection` | 读取 / 显式选用当前音频，PUT带选择版本号 |

取消、生成进度和下载继续使用既有接口。
