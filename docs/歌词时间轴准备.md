# 歌词时间轴准备

播放器按实际音频版本的开始、结束时间显示当前句，不按歌曲长度平均分配。

## 热歌推荐

固定热歌的歌词位于 `qf-server/src/main/resources/lyrics/samples/<track>.json`。
`sourceKey` 由曲目 ID 与 `RecommendationSamples` 中带内容哈希的音频对象名共同生成。
更换音频后旧时间轴不会命中新版本。公开 GET 只读数据，不提交识别任务。

原始文件没有供应商时间轴时，优先用准确原稿离线强制对齐；没有原稿才识别候选文字，再校对。
`scripts/align-sample-lyrics.py` 使用本地 Qwen3-ForcedAligner-0.6B，
按原稿与实际音频取得词级时间，再使用
`scripts/prepare-sample-lyrics.py` 校验音频 SHA-256、时序及识别结果，生成发布资源。
时间缺失、异常重复或被截断的结果不得按成功发布。歌词文字仍可能需要人工校对。

长音频按实际演唱段落分段，单段不超过 180 秒；分段清单绑定音频 SHA-256，
引用原稿行号以保留重复副歌，不用平均分配时长。分段边界来自音频识别锚点，
每段仍由对齐模型计算具体句子的时间。候选、分段结果和失败记录留在本机，可继续复用。
本次四首缺失原稿采用用户补充的原文；另一首英文歌复用已实测成功的词级识别结果对齐原稿。

本次中文长音频经 KIE Nemotron 实测有文字但无词级时间，已拒绝作为有效时间轴。
探索阶段的离线识别候选保留在本机，不把误识别文字替换进已有原稿。
最终对齐工具的独立环境依赖见 `scripts/lyrics-alignment-requirements.txt`。
模型固定版本为 `c7cbfc2048c462b0d63a45797104fc9db3ad62b7`，权重 SHA-256 为
`47831d0e82f96b20e9034dba01a075ee06436654719f6a68289e49f1b65ce0e7`，运行前校验。
该工具不属于日常 Web 服务依赖，运行不访问数据库或模型 API，也不自动下载模型。

## 广场和新歌

音频归档成功后，由独立后台线程扫描并准备时间轴。历史回填范围为广场当前公开作品；
以后新增音频以数据库保存的首次启用时间为界。重启保留扫描起点，期间归档的歌曲不会漏掉。
原先的私人历史作品不自动批量识别。已有 READY、正在手动同步或结果未知的时间轴不覆盖。

优先读取 KIE 原始演唱时间轴。明确失败后，最多补一次音频识别；提交超时或响应不明时
进入 UNKNOWN，禁止自动重发。已返回外部任务 ID 的任务只查询结果，重启不会重复创建。
结果查询连续失败最多五次，供应商等待最多三十分钟，记录保留供核对。

任务以 `asset:<assetId>` 去重。删除作品或音频版本后不再提交，迟到结果也不挂回已删除音频。
手动同步和自动准备采用一致的数据库锁顺序。后台不调用用户积分计费或用户免费改写额度。
供应商调用有独立每日上限，已有结果的读取不消耗模型额度。

## 配置和迁移

本次新增 V49，只在隔离库验证。生产迁移、配置启用和服务重启需另行上线授权。

```properties
qingfeng.lyrics.preparation.enabled=true
qingfeng.lyrics.preparation.scheduler-enabled=true
qingfeng.lyrics.preparation.daily-limit=40
qingfeng.lyrics.preparation.delay-ms=5000
qingfeng.lyrics.preparation.initial-delay-ms=30000
# 私有配置填写可调用识别模型的 Key，不得写入 Git
qingfeng.lyrics.preparation.transcription-api-key=
```

两项启用配置默认均不开启。日常 `scripts/start-main.ps1` 额外显式关闭这两项，
防止本机连接主库时运行后台准备。歌词后台使用自己的单线程，不占音乐生成和支付调度线程。

广场端只公开当前可见发布版本已归档的歌词，撤回、设为私密、版本替换和删除后重新校验权限。
PREPARING/FETCHING 时播放器有限轮询，准备好后更新当前句；切歌或关闭即丢弃过期响应。

热歌与广场的公开歌词 GET 必须同时通过 Web 安全规则及内测门禁。
真实清单回放测试使用随机本地端口、隔离 H2 库和开启的门禁，经完整 HTTP 过滤链读取；
同时检查未知热歌、错误发布版本、私密作品与写接口不能通过该只读入口访问。
