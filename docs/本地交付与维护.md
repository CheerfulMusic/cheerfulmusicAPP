# 本地交付与维护

## 构建与运行

在项目根目录执行`./scripts/build-local.ps1`，依次完成Vue类型检查/构建/测试以及Maven clean verify。Vue产物打入Spring Boot可执行包，`qf-server/target`下的Jar可以同时提供网页和API。

`./scripts/start-local.ps1 -Port 8081`会后台启动MySQL模式并检查健康状态；`./scripts/stop-local.ps1`只停止由脚本记录且创建时间匹配的进程，不按端口杀死其他应用。记录与日志位于`.cache/runtime`。私有配置、数据库和音频目录不在Jar中。

启动时将Jar复制到运行目录，避免Windows锁住构建产物。统一构建脚本在后端打包前停止它记录的项目预览；构建成功后再执行启动命令，不会直接复用旧构建。

网页入口为`http://127.0.0.1:8081`。直接刷新`/works/{id}`、`/gift/{token}`、`/account`由后端转入Vue，API仍独立鉴权。后端已检查对前端资源的公开放行，不因此开放个人数据。

开发模式：`./scripts/start-local.ps1 -Dev -Port 8081 -WebPort 5173`。手机同网调试：加`-Lan`并使用电脑局域网IP和网页端口，不使用手机自己的localhost。真实iOS/Android设备兼容性仍需要设备实测。

## 身份与作品找回

页面导航“找回作品”进入`/account`。先生成并保密保存一次性找回码；服务器只保存SHA256，不保存明文。重新生成会停用旧码；使用找回码会恢复相同创建者，并立即消费此码，恢复后要生成新的找回码。

恢复会切换当前浏览器身份，不合并两个身份的作品。已有其他设备会话继续有效；本版没有手机验证码、邮箱账号或集中退出所有设备功能。找回码属于私人访问凭据，不能替代分享链接，也不能发给收礼人。

## 存储与容量

默认本地：`qingfeng.media.storage=local`，`qingfeng.media.directory=./data/audio`。相对路径基于后端工作目录，建议长期使用固定绝对目录。单文件20MB，个人默认1GB（`qingfeng.media.creator-capacity-bytes`）。上传先原子预留20MB，成功后按实际字节结算，因此可用容量不足20MB时拒绝新上传，即使文件较小。

本地历史存储键与新键`local:`兼容；云端资源使用`oss:`前缀，改变新上传位置不会让旧本地音频失效。保留原目录，不会自动搬迁历史文件。

阿里云配置使用`qingfeng.oss.endpoint/region/bucket/access-key-id/access-key-secret`；也支持环境变量`OSS_ENDPOINT/OSS_REGION/OSS_BUCKET/OSS_ACCESS_KEY_ID/OSS_ACCESS_KEY_SECRET`。Endpoint使用HTTPS官方地域地址，例如`https://oss-cn-hangzhou.aliyuncs.com`，region为`cn-hangzhou`。密钥仅通过私有配置或环境变量提供。

将`qingfeng.media.storage`改为`oss`后，新文件先本地暂存校验，再由Java SDK V4签名上传私有对象。Bucket需预先创建；应用不会创建Bucket。RAM身份需要本项目对象前缀下的上传、读取、元数据读取、删除和设置对象私有ACL所需权限。接口仍经后端授权读取，不把Bucket改为公共，不把云端密钥放到前端。[阿里云官方SDK与私有ACL说明](https://www.alibabacloud.com/help/en/oss/developer-reference/oss-java-sdk/)。

目前使用后端流式中转以保证撤销后的新请求立即受控；未来流量增长时可换短期签名URL，同时明确已签发URL的撤销窗口。当前没有完整音频解码、转码或病毒识别。

## 备份与独立恢复

推荐先停止项目服务，再运行`./scripts/backup-local.ps1`。备份在`.backups/{时间}`，包含SQL、已校验的本地音频和SHA256清单，不包含数据库密码或模型密钥。仅当前用户可读的临时MySQL客户端配置会在操作后清理，密码不放进进程参数。

恢复命令：

```powershell
./scripts/restore-local.ps1 -BackupPath 'E:\qingfeng_AI_music\.backups\实际备份目录'
```

只创建新的`qingfeng_music_restore_`前缀数据库和`.cache/restores/{库名}/audio`，拒绝覆盖原库或现有目录。先校验清单，再导入并重新核算容量。验证恢复时必须同时把测试服务的数据库URL和媒体目录指向恢复结果，不要只切数据库。

默认备份要求项目停止写入。`backup-local.ps1 -Online`仅适用于本版“音频不可变、无在线文件删除”的运行方式，并要求不同时做文件整理；先取事务一致SQL，再复制音频，恢复时重新核算上传预留容量。将来引入删除/替换或自动清理后需重新设计在线快照。

如果数据库已引用OSS对象，本脚本拒绝声称生成完整本地备份。云端媒体需要对象版本控制/备份或同步到专用备份位置，SQL仍要单独保存；尚未实施完整OSS灾备。

## 存储维护

停止项目后运行`./scripts/maintain-local.ps1`只检查。加`-Quarantine`会把超过24小时、无数据库引用的本地文件移到`.cache/quarantine`，不永久删除，不跟随链接，不处理工作区外目录。应先备份；需要恢复时按隔离目录记录的文件名移回原音频目录。

加`-RepairCapacity`按已登记音频重算容量，释放进程异常退出遗留的保守预留。云端孤儿对象未自动整理，可按专用前缀和云端清单人工核对，不能用整个Bucket的生命周期规则误删正式音频。

## 音乐任务执行开关

`qingfeng.generation.enabled=false`保持当前暂停状态。即使配置了模型密钥，UnavailableMusicProvider也不会发起请求。

执行基础设施已实现：数据库扫描、任务/供应商租约与心跳、同一供应商单个在途生成、提交前持久化、重启查询恢复、归档唯一键、退避与只重试音频保存。未知提交会占用在途名额并等待核对，不能通过重启重新提交。临时下载失败可只读查询刷新结果地址。

启用真实供应商前仍需验证适配器，确保请求有超时、明确区分“已拒绝”与“可能受理”，配置`qingfeng.generation.audio-hosts`为实际可信HTTPS CDN主机名。默认列表为空，下载器拒绝未批准地址、内网地址和越界跳转。真实模型余额及供应商端行为未验收时保持关闭。
