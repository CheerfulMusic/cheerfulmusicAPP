## 两项音乐权限

1. 完成公司开放平台开发者资质认证，登记移动应用。记录应用详情里的移动 AppID。
2. 以该移动 AppID 和音频网页域名 `cheerfulmusic.com` 先申请**音乐类型分享权限**，保存微信开通结果。申请途径以该账号移动应用的权限页和官方音乐分享说明为准。
3. 使用**同一移动 AppID 和同一域名**申请**音乐视频类型分享权限**。官方要求按邮件模板提交，并按微信回复办理协议签署。这个类型可提交歌曲音频，好友或朋友圈的听众可以进入微信原生播放器。[微信 Android 音乐视频分享与注意事项](https://developers.weixin.qq.com/doc/oplatform/Mobile_App/Share_and_Favorites/Android.html) · [微信 iOS 音乐视频分享与注意事项](https://developers.weixin.qq.com/doc/oplatform/Mobile_App/Share_and_Favorites/iOS.html)

## 客户端配置与现场验收

在前端目录执行 `npm ci`、`npm run native:build` 和 `npx cap sync android`。移动构建使用 HTTPS 生产 API。Android 在私有 Gradle 属性或构建环境中设置 `QF_WECHAT_MOBILE_APP_ID`，使用 JDK 21、Android SDK 36 与 Gradle wrapper 运行 `:app:assembleDebug :app:assembleDebugAndroidTest`。连接测试设备后运行 `:app:connectedDebugAndroidTest`，验证微信消息构造与分享目标。公司正式包由持有签名证书的人签名。可以使用 Android build-tools 的 `apksigner verify --print-certs <APK>` 核对实际签名。

iOS 需在 macOS 执行 `npm run native:build`、`npx cap sync ios`，打开 `ios/App/App.xcworkspace`，选择公司 Team，设置构建项 `WECHAT_MOBILE_APP_ID`，启用 Associated Domains。公司提供签名中实际的 Application Identifier Prefix 后，本地生成 AASA 文件如下，检查内容再通过正常上线流程部署，服务器须以 JSON 响应且可直接访问。微信平台、客户端及 AASA 的路径须一致。[微信 iOS 接入指南](https://developers.weixin.qq.com/doc/oplatform/Mobile_App/Access_Guide/iOS.html) · [苹果关联域名说明](https://developer.apple.com/documentation/xcode/supporting-associated-domains)

```sh
node scripts/wechat-aasa.mjs ACTUAL_APPLICATION_IDENTIFIER_PREFIX > apple-app-site-association
```

- 两台手机分别安装公司签名的候选包和微信。App 首页可粘贴创作者已经公开的歌曲地址；「我的作品 → 分享歌曲」也提供两个分享目标。
- 用授权样曲[《下一波，我还在》V5](https://cheerfulmusic.com/song/grQVIB4zmKxV_ueWTppQgiLwS3WEIHiuRHfsvyXU27M)在 Android、iOS 各发一次给好友和朋友圈，记录发送方微信版本。接收方使用另一账号验证，点微信卡片的播放控件，确认播放、歌曲封面、歌名和创作者，记录是否打开了网页。接收者仅需微信。
- 在微信原生播放器选择歌曲来源，已安装 App 的设备应回到对应歌曲。回到 App 读不到公开资料时，应显示已撤销或已过期。
- 使用单独授权的测试作品验证撤销。对已发送的卡片发起新的音频请求须受公开权限控制。微信已经加载的音频和卡片外观由客户端管理。
- 保留每次实测结果。发送请求被 SDK 接收只代表微信接手，最终卡片样式、播放和实际发布以真机为准。
