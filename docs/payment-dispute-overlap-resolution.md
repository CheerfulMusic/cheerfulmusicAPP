# 首次败诉与退款重叠的安全保留契约

本变更仅针对无法证明退款和拒付净损失是否重复的路径；不新增迁移，不重新计算或合并不明资金损失。实际验收状态由本轮测试收据记录，本文件不是测试通过证明。

## 持久表示

同一已付款订单先有成功退款、随后首次收到部分 `LOST` 时，不能因无法自动去重而回滚唯一的争议记录。当前修复保留全局资源绑定，将该争议记录为 `UNKNOWN`、`loss_minor=NULL`，冻结对应批次 `max(0, original-consumed-adjusted)`。该用户的其他订单不冻结。

原始已核实的 `LOST` 观测和候选本金金额保存在 append-only `p0_credit_financial_audit`：

`fact = LOST_OVERLAP:<SHA-256(dispute ID)>:<version>:<candidate loss in minor units>`，`delta=0`。

订单关联保存在 `order_id`；渠道、商户、环境、原付款、用户和完整争议ID保存在既有绑定及争议表中。最长 `fact` 为117字符，未超过现有128字符限制。此金额只是待审核的损失观测，不是已执行永久调整，不能计入 `currentLosses`。可以通过 `fact LIKE 'LOST_OVERLAP:%'` 加订单与争议 `UNKNOWN` 查询待核查项，不依赖临时日志。审计历史本身不会在解冻后删除。

同用户首锁使重复通知串行，完全相同的争议、版本和金额只产生一条观测审计与一次实际冻结变化。相同版本却改变候选损失的请求拒绝。先前已经执行的永久损失不会被改成NULL；后续模糊观测保留它，并将批次置为 `REVIEW`，需要独立权威解除，普通OPEN或WON不能抹掉既有永久事实。

## 后续恢复

- 未执行过永久损失的 `UNKNOWN` 后获更高版本WON，可以解除该争议的冻结；其他未决争议和订单级REVIEW仍维持冻结。
- 消费失败按原分摊返还时，该订单重新增加的剩余权益也必须保持冻结。
- 若精确退款反转事实移除了重叠，可再次核实原LOST快照。仅当原同版本、同金额的 `LOST_OVERLAP` 观测存在且当前不再有重叠时，允许同版本UNKNOWN进入LOST并执行唯一永久调整。一般UNKNOWN不具备此豁免。
- 退款与败诉实际重叠关系仍不明确时，不自动把两者相加，也不自动猜减其中一项。保持待核查和冻结；该修复本身不代表已具备人工永久净额裁决入口。
