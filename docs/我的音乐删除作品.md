# 我的音乐删除作品

2026-11-09，本地开发，未上线、未重启业务服务。

## 用户行为

- 每张作品卡片增加“删除作品”，包括制作中、结果待核对、已完成和草稿。
- 已完成或已有音频的作品先显示警告：无法在“我的音乐”找回、原分享链接失效，请先下载。
- 制作中的作品也先确认，并说明删除不能保证取消供应商任务、不自动退款。
- 制作中作品在点击删除前刚好完成时，后端要求再次确认；前端升级为已完成警告。
- 删除成功后刷新当前页；删除失败保留作品、允许重试；双击、轮询返回及身份切换不应将卡片错误恢复。
- 当前作品正在播放时停止播放；更新播放队列，移除已删除作品。

## 实现和数据边界

新增 `DELETE /api/app/works/{id}?acknowledgeCompleted=true|false`，沿用会话、CSRF和归属校验，返回明确的 `{deleted:true}`。重复删除幂等，其他账号无权删除。

采用软删除：`music_work.deleted_at` 标记，列表、详情、更新、公开分享读取均过滤删除状态。后台任务、计费审计和媒体记录保留，正在执行的任务继续完成也不会将作品恢复显示。已有短期媒体签名地址或已下载文件不会被立即收回。

本轮不是OSS物理清理或隐私数据擦除功能，不自动删除音频/封面文件，也不自动释放文件容量、取消供应商任务或退款。

## 数据库迁移

新增 `V24__work_soft_delete.sql`，增加可空删除时间和列表索引。仅在隔离测试库验证，未连接生产执行。正式发布时必须先按既定流程备份、核对迁移并部署匹配JAR；不能只更新前端或将新后端直接指向未迁移的生产库。
