## 修复内容

| 编号 | 现在的行为 | 关键代码 |
| --- | --- | --- |
| R1 响应不完整被当成功 | 读取响应体期间的超时、连接中断继续抛错；非法 JSON、空对象及缺少必需字段的成功响应视为结果未确认。普通请求与上传使用同一个解码器。只有明确声明的无返回值接口允许空响应。 | `Qingfeng_AI_Music_VUE/src/shared/http/api-client.ts`、`response-contracts.ts` |
| R2 媒体登记失败后误删文件 | 文件写入完成后，在独立短事务内完成资产登记、默认选择和容量结算。只在尚未开始登记或事务明确回滚时删文件并退回全部预留；成功的重复归档只删除本次多余文件。 | `MediaService`、`MediaRepository`、`MyBatisMediaRepository`、`GiftConfiguration` |
| R3 新建继续修改旧草稿 | 初始化同时识别 `work`、`draft` 与全新入口；仅移除 `draft` 也会重建独立向导。内部补全地址只跳过对应的那一次初始化。旧请求响应不能把新页面带回旧作品。 | `DraftStudioPage.vue` |
| R4 旧设置响应污染新作品 | 等待歌词保存前固定作品 ID、版本、设置快照及组件实例；每次异步返回都核对页面代次。切到 B，甚至 A→B→A 后，旧请求都不能改写新页面、关闭新设置面板或清除新编辑。 | `WorkDetailPage.vue` 的 `applyMusicSettings` |
| R5 多标签覆盖本机草稿 | 每个文档写自己的分支，每次先写新的不可变副本，再删除自己上一份。旧标签只读其他分支，不覆盖或删除它们；无内容变化时保留原编辑时间。故事和歌词页均可查看时间、内容并显式恢复副本。 | `shared/drafts/recovery.ts`、`RecoveryCopies.vue`、故事页、歌词面板 |

R1 的 `INVALID_RESPONSE` 使用状态 `0` 表示提交结果未确认，保留调用方的请求标识与本机内容，不自动重放写入。已确认的 HTTP 错误仍保留其原状态码。音乐设置和目录也校验偏好、标签显示与生成所依赖的字段。

R2 没有把网络下载或文件写入放进数据库事务。若事务完成状态未知，文件和预留容量会保守保留，**本轮没有新增自动核账或孤儿清理机制**；后续应核对实际资产记录再结算，不能直接全额退还或删除文件。测试覆盖提交后异常，并未模拟真实 MySQL 网络断线。

R5 恢复前会另存当前内容；如果浏览器存储已满或不可写，就停止恢复，保留当前编辑并提示先复制。旧格式恢复记录仍可读取；有效副本保留 7 天，过期的不可变副本按需清理。本机草稿仍属于浏览器存储，不能代替账号跨设备同步，也不能代替服务端的版本冲突检查。
