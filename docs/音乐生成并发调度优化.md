# 音乐生成并发调度优化

日期：2026-11-08。范围：本地 `main` 源码；本轮不发布、不重启本地业务服务或线上服务，不修改生产数据。无新增数据库迁移。

## 问题与改动

原领取 SQL 在同一供应商存在 `SUBMITTING / RUNNING / SAVING` 时禁止领取下一首排队任务，Worker 又在整段提交、查询或归档期间持有供应商租约，导致配置允许多人创作时仍实际串行。

现在使用已有的 `generation_worker_lock` 行，仅在独立的 READ COMMITTED 短事务中串行化“检查名额、选择任务、写入任务租约”。事务提交后立即释放数据库行锁，网络请求、下载和 OSS 上传不占用该锁。

- 每个供应商默认最多分发 3 首在途任务。
- `SUBMITTING / RUNNING / SUBMISSION_UNKNOWN` 及已领取且租约有效的 `QUEUED` 都计入在途名额，避免多 Worker 先领取再超发。
- `SAVING` 不占用供应商生成名额，归档有独立的执行线程预算。
- 无供应商编号的未知结果不自动重提，仍占用在途预算，避免未知成本被无限放大；已有编号的未知任务继续只读查询。
- 提交、查询和归档分别执行，慢上传不会阻塞新提交或其他任务的查询。
- 各阶段使用固定数量的循环，没有无界执行队列；单次异常后继续下一轮扫描。
- 整个应用发出就绪事件后才启动调度，避免其他Bean初始化失败时提前调用付费生成。
- 心跳只续约当前任务。开始付费提交必须同时满足任务状态、令牌和未过期租约。
- 旧 Worker 的释放与续约不能覆盖新 Worker 的任务租约。已有的撤销窗口、提交幂等、查询退避、归档重试和积分规则保留。

兼容既有供应商租约字段和方法：若旧进程仍持有供应商租约，新领取暂不越过该租约。上线仍建议沿用既定的单服务发布流程，避免未经验证地混跑多个版本。

## 配置

集中配置文件：`Qingfeng_AI_Music/config/usage-limits.properties`，启动参数或私有配置可按 Spring 优先级覆盖；调整后需重启对应后端进程。

```properties
# 原有请求准入：保持每人1首、全局最多3首活跃任务
qingfeng.usage.music.concurrent-per-creator=1
qingfeng.usage.music.concurrent-global=3

# 执行预算：同一供应商的在途分发上限
qingfeng.generation.max-in-flight=3

# 以下线程数为每个应用进程的预算
qingfeng.generation.submit-workers=1
qingfeng.generation.query-workers=2
qingfeng.generation.archive-workers=1

# 每个执行循环完成后等待的间隔，默认3000毫秒
qingfeng.generation.scan-ms=3000
```

准入上限与分发上限用途不同。原有准入还会统计排队、归档和待核对任务，不会因为移除串行限制而放开无限请求或增加单人额度。

提交线程默认1个，每次调用结束后等待扫描间隔，再领取下一个任务。该节奏是每进程限制，不是供应商账号级跨实例 RPM 限流；本轮不引入新的分布式速率限流。多实例或提高配置前仍需确认真实供应商配额、数据库连接池、带宽和预算。

## 暂停与回退

- 将 `qingfeng.generation.max-in-flight=1`，可收紧为最多1首在途生成；归档继续独立推进。
- 将该值设为 `0`，只暂停新任务分发，已受理任务仍可查询和归档。
- 不用关闭整个 `generation.enabled` 或调度开关来代替“暂停新分发”，否则原任务的查询、归档也会停止。
- 需要回退实现时沿用发布版本回切流程。本轮未改表，但历史任务状态与原租约仍应保留，不能通过清库或删除任务回退。

## 验证

1. 调度器测试：阶段隔离、线程预算、重复启动保护、异常后继续扫描、关闭与参数边界、应用就绪前不分发。
2. 任务集成测试：不同用户同时生成、上限限制、有效排队租约占额、租约续期、过期 Worker 禁止开始提交、旧令牌不能释放新租约、慢归档不阻塞提交查询、暂停新分发后原任务可完成。
3. 保留并运行原有重复提交、撤销、未知结果恢复、归档重试与积分相关回归。
4. 在独立数据目录启动 MySQL 8.0.40，端口57286，固定测试库 `qf_execution_concurrency_test`，执行相同的21项任务回归，全部通过；随后正常关闭测试实例。没有使用生产主库。

真实 MySQL 回归入口：`GenerationWorkerMySqlIntegrationTest`，默认跳过；仅显式设置 `QF_EXECUTION_MYSQL_TEST_PORT` 为57xxx端口时运行。测试必须使用独立临时数据目录，不得指向日常数据库。

```powershell
# 仅在独立临时MySQL已准备、确认端口与数据目录后使用
$env:QF_EXECUTION_MYSQL_TEST_PORT = '57286'
mvn -pl qf-server -am '-Dtest=GenerationWorkerMySqlIntegrationTest' '-Dsurefire.failIfNoSpecifiedTests=false' test
```

所有供应商和下载均使用离线替身，未进行真实付费生成。上述测试验证调度正确性，不代表真实供应商的容量、输出质量或线上用户规模已经验收。

后端完整 `mvn verify`：业务模块23项通过；服务模块318项中297项通过、21项临时MySQL专项按设计默认跳过，常规合计320项通过。被默认跳过的21项已在上述独立MySQL实例另行执行并全部通过。
