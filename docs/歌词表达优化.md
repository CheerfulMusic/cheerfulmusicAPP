# 歌词表达优化

2026-11-03，本地代码已实现。保持现有DeepSeek模型、一次请求和生成额度规则，不自动增加二次润色调用。

## 默认写作方向

提示词由独立的`LyricsWritingPrompt`维护，重点从“简洁、押韵、完整”扩展为：

- 从用户提供的物件、动作、习惯或原话中找1至3个具体细节，用场景承载情感，避免只复述“你对我很重要”。
- 主歌写经历，第二段增加理解或视角变化，桥段推动情绪；副歌围绕故事里的核心意象形成短而有回味的记忆句。
- 减少重复赞美、空泛祝福和不依附故事的宏大词汇；保留适当留白，避免把“深意”写成晦涩词语或散文说教。
- 根据明确的关系、场景和风格调整表达，不把父母、朋友、孩子或写给自己的歌一律写成爱情或苦情歌。
- 不擅自增加婚姻、分手、病痛、离别等人生事件；素材少时简洁表达，不凭空补一段故事。
- 兼顾短句、呼吸感与自然押韵；说唱、儿歌等保留各自的表达方式，不强制所有作品使用完全相同的段落长度。
- 中英混合让两种语言共同推进情绪，不逐句重复翻译。指定保留的原句、段落和语言安排优先保留。

写作自检在同一次请求中完成，接口仍只接收`title`和`lyrics`两个JSON字符串，不展示模型的检查过程。

## 页面入口

故事输入增加具体细节引导。歌词页“想换个写法？调整并重新生成”中新增五个可多选方向：更含蓄一些、更多画面感、少些套话、副歌更难忘、情绪有递进。

点选方向只补充可编辑的修改要求，不立即调用模型；可取消其中某个方向，保留用户自行填写的其他内容。切换中英文界面保持选择和原要求；刷新可以恢复，1000字符上限仍有效。

重启后端后，新请求使用新提示词。已有歌词和歌曲不自动修改；需要在歌词页主动点击“重新生成歌词”。旧版本保留，相同请求键仍返回原结果，避免提示词升级造成重复扣费。

## 验证边界

本轮使用本机HTTP模拟DeepSeek，检查新写作要求确实发送、用户故事和修改上下文完整保留、中文/英文/混合语言规则，以及一次请求不自动追加第二次生成。前端检查界面文案、润色方向和本机恢复。

模拟输出不能证明真实模型一定写得更好；真实歌词的细腻程度、可唱性和最终歌曲效果仍需后续生成对比。本轮没有调用真实付费模型。
