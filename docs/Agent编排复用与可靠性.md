# Agent 编排复用与可靠性

本次在现有 Java 服务内增强意图理解、工具调用、执行进度和模型故障处理，不增加 Dify、Python 服务或新的数据库。模型只提出计划，业务执行仍经过原有权限、用户意图、确认、预算、积分事务和幂等请求键。

## 执行链

1. POST `/api/app/agent/conversations/{id}/messages` 使用原有准入、期限和持久请求键。
2. 模型可返回原生 function `tool_calls`，或既有 JSON 计划。工具目录和参数 schema 来自服务端代码，不接受模型自行提供的定义。
3. 统一解码器将结果转为 `Plan/Step`。每次最多六步，原有生成次数、确认、对象版本和写入授权继续生效。所有真实工具仍由 `AgentChatService` 执行，流式观察不走另一套工具循环。
4. 查询结果可以进入原有一次再规划；不会因为换了协议扩大模型调用次数或自动执行无限循环。
5. 真实的规划、工具开始和结果阶段写入现有会话消息。阶段消息不进入后续模型历史，不替代最终业务结果。

## 熔断与降级

配置仅作用于对话规划模型：

| 配置 | 默认值 | 含义 |
|---|---:|---|
| `qingfeng.agent.intent.circuit.failure-threshold` | 3 | 达到连续模型故障次数后开启熔断 |
| `qingfeng.agent.intent.circuit.cooldown-seconds` | 30 | 冷却时间；到期只允许一个探测请求 |
| `qingfeng.agent.progress.enabled` | true | 保存真实执行阶段消息 |
| `qingfeng.agent.events.maximum` | 32 | 单进程同时观察连接上限 |
| `qingfeng.agent.events.per-owner` | 2 | 每个账号同时观察连接上限 |

只把 `AGENT_CHAT_UNAVAILABLE` 记为模型故障。取消、请求期限、预算和上下文过大等错误保持原样。旧的在途请求完成后不能错误关闭新一轮熔断。每个请求不自动重试，不自动切换另一个付费模型。

降级只接受明确整句且目录声明为 `read` 的查询：作品列表、积分余额、可用功能。生成、删除、支付、分享、复合指令及引用文本不通过规则猜测执行。只读结果仍由当前账号原有业务服务返回；没有模型时不会返回假歌词、假音频或假付款成功。

熔断是每个 JVM 的可用性保护，不能替代原有数据库/Redis 准入、账本事务和跨实例限额，也不代表已经部署多节点高可用。

## 实时进度与恢复

GET `/api/app/agent/conversations/{id}/events?afterSeq=...&historyEpoch=...` 是只读 SSE：

- `state`：与原 `/state` 相同的持久快照，携带历史代次和序号；角色状态更新保持 upsert。
- `ping`：连接心跳。
- `error`：观察失败，不表示业务任务已取消。

观察入口要求当前账号拥有会话，不创建会话，不调用模型，不提交任务。连接最长 30 秒；观察线程与订阅总量有界，取消任务从调度队列移除。数据库访问仍受现有连接池与查询能力约束。

前端使用 Fetch SSE，处理 CR/LF、UTF-8 分片和多行 data，并校验消息归属。断开、不支持、格式异常或心跳超时后降级为 GET 增量轮询，不重新 POST。最终客户端动作和授权续做由原 POST 响应/恢复流程负责，观察消息不会重复播放、下载或提交下一轮任务。

模型规划 JSON 和内部推理不直接展示；页面展示真实执行阶段。普通聊天回答仍在模型完整返回后保存，这次没有伪造逐字输出。

## 验证和上线边界

测试使用离线模型替身、loopback HTTP 和 `test` profile 的 H2；不连接主库，不执行真实支付或付费生成。覆盖原生工具解析、参数约束、熔断并发与半开、断流恢复、会话隔离、请求重放和只读 SSE。

本次没有新增数据库迁移。代码验证后合并本地 main；本地运行版本和线上部署需要分别切换，代码合并本身不改变运行服务。
