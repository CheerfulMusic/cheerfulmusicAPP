## 修改位置

- 本地：`Qingfeng_AI_Music/config/usage-limits.properties`。
- 线上：`/etc/qingfeng-music/usage-limits.properties`。

额度、并发数和每日时区都在该文件中统一管理。不要再把额度复制到 `local.properties` 或私有 `application.properties`。Java 的配置装配仅读取必填项，不保存另一套数字默认值；缺少必填配置或填入非法值时启动失败。

对于已经包含对应实现的运行版本，修改配置并重启后端即可生效，无需重新打包。新增调度或限流代码时仍须发布匹配JAR。线上配置变更与重启须先获得明确上线授权。当前不提供热更新。

## 取值

| 值 | 含义 |
| --- | --- |
| `-1` | 不限制该项 |
| `0` | 禁止新增请求 |
| 正整数 | 该项的实际数量上限 |

每类有四个独立配置：`daily-per-creator` 是个人每日上限，`daily-global` 是全站每日上限，`concurrent-per-creator` 和 `concurrent-global` 分别控制个人及全站正在处理的请求数。

例如当前音乐配置：

```properties
qingfeng.usage.music.daily-per-creator=-1
qingfeng.usage.music.daily-global=-1
qingfeng.usage.music.concurrent-per-creator=1
qingfeng.usage.music.concurrent-global=100
```

歌词、时间轴、封面分别使用 `lyrics`、`timing`、`cover` 前缀。测试期四类的每日个人和全站上限均为 `-1`；并发保护仍按文件配置生效。若将来设置个人20次、全站200次，两项分别填写20、200即可。

## 行为与打包

不限每日次数时仍保留使用记录、任务状态和请求幂等。同一请求重放不会重复占用，接口限流和同作品的任务保护继续生效。此次没有清空历史用量，没有通过后台自动调用模型来验收。

额度 API 返回 `dailyUnlimited=true`，`dailyLimit` 与 `dailyRemaining` 为 `-1`。页面显示“不限次数”，不会显示负数剩余次数。有限额度下原有剩余次数、每日重置和拒绝新增逻辑继续工作。

Maven 仅将公开的 `config/usage-limits.properties` 包含到 JAR 作为默认配置，明确排除私有 `local.properties`。本地 mysql profile 额外加载工作目录对应的公开配置；线上 `/etc/qingfeng-music/usage-limits.properties` 覆盖打包默认值。环境变量、命令行等 Spring 的高优先级覆盖机制仍可使用，日常维护应以这一个文件为准。

服务器的每日备份已增加该配置文件。恢复或回退应用时也应恢复对应配置；旧版本不支持 `-1` 的配置语义。
