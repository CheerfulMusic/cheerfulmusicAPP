# 新增推荐样曲的播放歌词

本次补齐 2026-11-19 新增的十首推荐样曲。音频、封面及 OSS/CDN 对象不变；不涉及数据库迁移或生产数据回填。

## 播放链路

- 前端识别 `/media/recommendations/<歌曲ID>-<音频SHA256前12位>-preview-128.mp3`，请求对应公开歌词接口，并携带 `audioHash`。
- 后端目录注册十首新曲。公开接口校验音频版本，从 JAR 内的 `lyrics/samples/<歌曲ID>.json` 读取已准备好的时间轴；资源的 `sourceKey` 还绑定具体 OSS 对象键。
- 《Euphoric Drop》按原始素材标注为纯音乐，返回 `INSTRUMENTAL`，播放器显示“纯音乐（无歌词）”。
- 其他九首读取实际录音的时间轴。歌单里的原始歌词文本保留，播放歌词按实际演唱顺序显示。
- 拖动进度和切歌继续使用播放器现有时间轴定位及过期响应隔离逻辑。公开播放不提交识别任务，不扣积分。

## 准备方式

离线识别使用已有的 Whisper large-v3-turbo 与 small 模型，结合固定版本的 Qwen3-ForcedAligner-0.6B 做分段对比。最终九首歌曲共 342 行，时间采用实际识别词的起止边界；识别字词有差异时对照用户原稿，重复、切片人声按录音顺序整理。不按歌曲总时长均匀分配时间；零时长、越界、明显重叠及无法确认的模型输出不直接打包。

模型权重 SHA-256：`47831d0e82f96b20e9034dba01a075ee06436654719f6a68289e49f1b65ce0e7`。工具与模型只在忽略提交的独立目录运行，不安装到 Java 服务或日常启动环境。

本批使用独立 CUDA 工具目录（PyTorch 2.11.0+cu128、Qwen 对比为 bfloat16，Whisper 为 float16）；原 CPU 工具环境及项目依赖保持不变。该环境不参与服务启动或用户播放。

`scripts/align-sample-lyrics.py` 支持检查过的媒体清单、显式语言、CPU/CUDA 设备及计算精度。生成候选后，`scripts/prepare-sample-lyrics.py` 再核对完整音频 SHA-256、对象键和时间范围，输出打包资源。新增或更换录音时必须重新校准；不能沿用旧录音的时间轴。

## 本地与发布边界

源码合入后，用 IDEA 重新编译、启动后端，并刷新开发前端即可读取新增资源。`scripts/start-main.ps1` 使用的既有运行版不会因为源码合并而自动更新。

本次不发布、不切换线上版本、不重启线上服务，不连接或修改主库。后续若发布，需要同时包含这次后端资源和匹配的前端代码。

- 前端全量：122 个测试文件、983 项通过；类型检查及正式构建通过。
- 后端针对性验证：38 项通过，包括全部 22 首目录歌曲的公开歌词 HTTP 返回、音频版本拒绝、旧客户端兼容及无 SQL/供应商调用校验。
- 离线工具：7 项通过，覆盖音频哈希、原稿段落过滤和重复段落的独立时间。
- 实际浏览器：十首音频均可播放；九首歌词各检查开头、中间、结尾的进度跳转，共 27 处；纯音乐提示、下一首切换及旧音频版本 404 均通过。
- 浏览器使用仅监听本机的临时适配服务，运行真实歌词控制器和打包资源、读取与 OSS 文件相同的本地音频字节。业务接口采用本机模拟响应，不连接数据库，不提交识别任务。此项验证不代表线上已更新。
