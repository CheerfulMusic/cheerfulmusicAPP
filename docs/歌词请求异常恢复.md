# 歌词请求异常恢复

## 2026-11-03 线上问题

线上仅一条歌词请求处于 `UNKNOWN`，对应作品没有保存成功的歌词；20 个音乐生成任务均为 `SUCCEEDED`。歌词和音乐分开限制并发，因此已有歌词的其他作品可以继续生成音乐。

旧版同步调用 DeepSeek 后，所有运行异常都将请求记为 `UNKNOWN`；它继续占用歌词并发名额，复用原请求标识也无法重新调用。旧版没有记录首次失败错误码，不能据此断言最初一定发生了超时、网络中断或无效输出。

## 修复

- 同步调用失败记为 `FAILED`，记录错误码、完成时间并释放并发名额。原请求标识与已用每日额度保留；同一旧标识不会再次调用模型。
- HTTP 调用超时 90 秒，数据库 `PENDING` 超过 3 分钟可转为失败。新请求准入和请求状态读取均可恢复这些遗留任务。完成结果使用事务内的条件状态更新，过期请求的迟到结果不能插入新歌词。
- V11 为旧记录增加错误码和完成时间，将旧 `UNKNOWN` 记为 `FAILED / LYRICS_LEGACY_RESULT_UNKNOWN`，不删除记录、不退还可能已消耗的额度、不修改旧歌词。
- `GET /api/app/works/{work}/lyrics/requests/{key}` 只允许作品本人读取，返回 `NOT_FOUND / PENDING / FAILED / SUCCEEDED`、结果版本和错误码。
- 歌词页恢复本机请求标识后先核对状态：失败则解除等待，成功则找回旧结果，处理中仅提供状态刷新。找回结果不覆盖本机未保存的修改。
- 用户明确再次编写时使用新请求标识；故事页继续制作也遵循此规则。不会自动重试模型调用。重新编写可能再次消耗平台费用及一次歌词额度。
- 生成错误使用“重新编写歌词”，保存错误使用“重试保存”；超时、网络中断和格式错误具备可区分的错误码。日志仅记录作品/请求标识、错误码、异常类型及必要的 HTTP 状态，不记录密钥、故事或供应商响应正文。
