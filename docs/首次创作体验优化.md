# 首次创作体验优化

本轮围绕「写故事 → 修改歌词 → 生成歌曲 → 送出礼物」改造，保留 Cheerful Music 黑色与橙红色品牌。结果页以专辑封面和试听为主，辅助操作折叠；手机底部保留主要操作。

## 本轮清单

- [x] 故事与歌词自动保存、本机恢复、失败重试和版本冲突保护。
- [x] 不必先保存草稿；一个按钮保存并编写歌词；一个按钮保存、确认歌词并生成歌曲。
- [x] 结果优先展示封面、试听、歌名、送礼；音频导入折叠。
- [x] 我的音乐展示真实状态、直接试听、生成期间更新状态。
- [x] 持久化个人/全站每日额度和并发限制，重复请求不重复占额。
- [x] 首次选择歌词语言，与界面语言独立；重新生成支持修改要求并保留旧稿。
- [x] 手机底部主要操作；歌曲完成后提示备份找回码。

## 额度规则

当前默认按 Asia/Shanghai 日期：歌曲个人 20 次/天、全站 20 次/天，个人同时 1 个、全站同时 3 个；歌词个人 20 次/天、全站 100 次/天，个人同时 1 个、全站同时 5 个。2026-11-03 按用户要求将原个人音乐 3 次/天提高为 20 次/天，歌词个人额度也由 10 提高为 20，便于连续创作新歌。通过 `qingfeng.usage.music.*`、`qingfeng.usage.lyrics.*` 配置覆盖；0 表示禁止新增。本应用限制的是准入次数，不是供应商余额或歌曲数量。

数据库行锁保护准入；请求登记/任务创建与额度预留在短事务内完成，模型 HTTP 请求不持有事务。相同请求键重放、查询进度、仅重试音频归档不额外占额。已准入请求保守记次，失败不自动退额；结果不明确的请求继续占用并发，需维护人员核实供应商账单与任务后处理。在途任务跨午夜仍占并发。

访客身份按浏览器会话识别，清除 Cookie/换设备可以成为新身份；个人额度不等于实名用户额度。全站上限独立执行，扩大开放前仍需账号与防滥用策略。V7 前任务纳入并发统计，历史调用不追溯扣次数。

## 本机恢复

副本保存在当前浏览器 localStorage，按创作者与作品隔离，最多保留 7 天；用于恢复，不替代数据库与找回码。自动保存不调用模型；冲突不自动覆盖另一页面。浏览器禁止存储时仍可保存到后端，并显示提示。
