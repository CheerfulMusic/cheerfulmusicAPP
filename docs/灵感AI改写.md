# 灵感 AI 改写（待发布）

2026-11-04，在创作页输入框顶部增加真实的“AI改写”按钮，复用后端现有 DeepSeek 密钥和模型配置。本轮未部署、未调用真实付费模型。

## 用户流程

1. 填写创作灵感，点击“AI改写”。空内容仅提示，不发模型请求。
2. 后端将原意整理成更具体、自然的创作描述，不直接生成歌词，不擅自添加真实人物经历，不将普通亲情改成恋爱或悲伤情节。改写保留原文主要语言，歌词语言设置作为后续参考。
3. 成功后先备份原文，再替换输入框；内容沿用既有自动保存。未经再次编辑的改写结果旁显示“恢复原文”，原文也保留在本机草稿副本中。
4. 用户确认或继续编辑后，另行点击“生成歌词”。改写本身不会提交歌词或歌曲生成。

失败时保留输入；服务不自动重试。改写中禁止重复点击与同时提交歌词，但用户仍可继续编辑。如果请求返回时原文、歌词语言、作品上下文或创建者已变化，旧结果不会覆盖新内容。

## 后端

`POST /api/app/inspiration/rewrite`

请求：`{"text":"用户创作描述","language":"zh-CN"}`。language 支持 `zh-CN`、`en`、`mixed`。

响应：`{"text":"改写后的创作描述"}`。

接口要求创建者会话及 CSRF，输入和输出均限制 4000 字符。外部调用超时 60 秒，前端等待上限 90 秒；无自动重试。只接受完整结束且包含有效 text 字符串的模型 JSON，不以空结果覆盖输入。

模块分工：业务接口 `InspirationRewriter`、应用服务 `InspirationRewriteService`；基础设施 `DeepSeekInspirationRewriter`；Web 入口 `InspirationController`。未新增数据库迁移，不在改写接口中写入作品或歌词。

配置沿用 `qingfeng.providers.deepseek.api-key` / `DEEPSEEK_API_KEY` 与 `qingfeng.providers.deepseek.model`。新选项位于 application.yml：

```yaml
qingfeng:
  inspiration:
    rewrite:
      enabled: true
      concurrent-global: 4
```

同一创建者同时最多一次改写，单实例全站并发通过配置控制，并沿用现有 API 请求限流。改写不计入歌词生成次数，但实际调用会消耗 DeepSeek 额度；多实例部署需后续改用共享并发管理。

IDEA 运行中的后端需要重启后加载新接口；开发模式前端热更新即可，未在本轮重启用户服务或部署线上。
