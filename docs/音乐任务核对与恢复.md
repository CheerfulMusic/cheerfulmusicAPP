# 音乐任务核对与恢复

`SUBMISSION_UNKNOWN` 表示本系统无法确认供应商是否受理。保留原请求标识和已用额度，不自动补发付费请求。

## 用户路径

1. 作品页显示核对提示，并持续读取本站记录。
2. 已有平台任务编号：Worker查询原任务，成功后继续音频归档；查询失败使用原有退避机制。
3. 没有平台任务编号：无法安全查询供应商。等待至少3分钟后，用户可明确确认结束本次等待；系统不会因此重新生成歌曲。用户可在平台已计费的情况下仍无法取回结果，界面会在确认前说明。
4. 结束等待后旧记录变为 `FAILED / CHECKING_CLOSED`。历史、计费预留和请求键保留，新的生成必须由用户主动点击。

## 后端约束

- 排队准入不再把其他待核对任务当作供应商全局忙碌。个人并发限额仍保护同一用户；无编号任务结束等待后才释放该占用。
- Worker只领取带平台编号的待核对任务，执行查询分支。无编号任务不会自动重提。
- `POST /api/app/works/{work}/generations/{task}/close-checking` 要求会话、CSRF和作品所有权，并要求请求体 `{ "acknowledge": true }`。
- 结束操作只适用于无编号、已等待3分钟且没有有效租约的待核对任务；条件更新避免与Worker争抢。重复关闭幂等，已关联平台任务不可由此丢弃。
- 本轮没有提供任意填写平台任务编号的用户接口，防止将同一API账户下其他用户的供应商结果绑定到自己的作品。
- 结束等待是用户明确放弃本站追踪，并不证明供应商未计费，也不构成平台任务取消。

## 版本管理

共享工作区仍有主线程和其他历史改动。本轮以修改前快照为基准生成独立补丁及SHA256清单，避免将其他未完成工作一并提交。没有切换共享分支、重置或清理工作区。应用补丁前应确认基线；不能将本补丁误认为整个工程的首次完整提交。

公网发布应在主线程完成当前任务、确认合并后的构建产物后进行，沿用已有备份和回退流程。
