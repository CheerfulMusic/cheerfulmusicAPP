# V27 / V28 迁移执行说明（生产库）

- 适用版本：歌词生成积分扣费 + AI 改写积分计费
- 执行方式：**手动执行**。部署侧 `--spring.flyway.enabled=false`，Flyway 不会自动跑迁移
- 目标库：`cheerfulmusic.com` 线上生产库 `qingfeng_music`（SSH 隧道 `127.0.0.1:13306`）
- ⚠️ 本文件只是执行说明，**不代表已执行**。执行前请确认已完成备份。

---

## 1. 前置检查

```sql
-- 1.1 确认当前迁移版本（应为 V26，且 V27/V28 不存在）
SELECT version, description, success, installed_on FROM flyway_schema_history ORDER BY installed_rank DESC LIMIT 5;

-- 1.2 确认目标表不存在（存在则说明已执行过，不要重复建表）
SELECT COUNT(*) FROM information_schema.tables
 WHERE table_schema = DATABASE() AND table_name IN ('credit_consumption','daily_quota','rewrite_consumption');

-- 1.3 记录执行前的账本基线，便于事后对账
SELECT COUNT(*) AS ledger_rows, COALESCE(SUM(amount),0) AS total_amount FROM credit_ledger;
```

同时完成：服务器当前 JAR、配置与数据库的备份（AGENTS.md 上线流程第 5 步），确认可回滚。

## 2. 执行迁移

按顺序执行两个文件（内容与仓库中的迁移文件逐字一致，**不要手改**）：

- `qf-infrastructure/src/main/resources/db/migration/V27__credit_consumption.sql`
- `qf-infrastructure/src/main/resources/db/migration/V28__rewrite_charges.sql`

V27 建 `credit_consumption`（歌词消费流水）；V28 建 `daily_quota`（每日次数配额）与 `rewrite_consumption`（AI 改写流水）。

**不需要改写 `flyway_schema_history`**：本项目部署关闭了 Flyway，表结构由 DBA 手工同步，版本号以代码为准。若贵方流程要求 Flyway 版本一致，请按贵方规范补充记录行。

## 3. 执行后验证

```sql
-- 3.1 三张表都已建好
SELECT table_name FROM information_schema.tables
 WHERE table_schema = DATABASE() AND table_name IN ('credit_consumption','daily_quota','rewrite_consumption');

-- 3.2 索引齐全
SELECT table_name, index_name FROM information_schema.statistics
 WHERE table_schema = DATABASE() AND table_name IN ('credit_consumption','daily_quota','rewrite_consumption')
 GROUP BY table_name, index_name;

-- 3.3 账本未被改动（应与 1.3 一致）
SELECT COUNT(*) AS ledger_rows, COALESCE(SUM(amount),0) AS total_amount FROM credit_ledger;

-- 3.4 外键指向 creator
SELECT table_name, constraint_name FROM information_schema.table_constraints
 WHERE table_schema = DATABASE() AND table_name IN ('credit_consumption','daily_quota','rewrite_consumption')
   AND constraint_type = 'FOREIGN KEY';
```

## 4. 回滚

三个表都是**新增**，不影响既有数据，回滚只需删表：

```sql
DROP TABLE IF EXISTS rewrite_consumption;
DROP TABLE IF EXISTS daily_quota;
DROP TABLE IF EXISTS credit_consumption;
```

⚠️ 若回滚前已经产生过扣费数据，`credit_ledger` 里的 DEBIT/REFUND 记录需要单独核对，不要直接删表了事。

## 5. 注意事项

- **不改历史迁移**：V1–V26 一律不动，本次只新增 V27/V28。
- **执行顺序**：必须 V27 → V28（V28 依赖 V15 的 `credit_lock` 与 `creator` 表）。
- **时区**：`daily_quota` 与 `rewrite_consumption` 的「当天」按 `qingfeng.usage.zone=Asia/Shanghai` 计算，与既有日配额一致。
- **不要写测试数据**：自动化验证不得向主库写入夹具或模拟支付成功数据。
