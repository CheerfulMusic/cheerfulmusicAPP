## 补丁与版本边界

`changes.patch` 基于本侧聊开始修改前的工作区快照生成，包含本次代码、测试和文档差异。`manifest.json` 记录该基线与修改后文件的SHA256、当时Git HEAD及补丁哈希。它不是从旧HEAD直接应用到全新检出的完整功能包，依赖工作区已有的生成、额度、封面等实现。

共享工作区已有大量主线程和历史改动。本次没有切分或提交这些改动，没有移动main、改暂存区、清理文件或推送GitHub。本次独立补丁提供可追溯、可审查的变更记录；整个工程的Git提交整理仍应在主线程完成当前工作后进行。

检查补丁时可先执行 `git apply --check changes.patch`；已包含修复的工作区使用 `git apply --reverse --check changes.patch` 检查逆向适用性。两者均只检查；不要在共享工作区直接执行应用或撤销命令。合并时应先对照文件哈希，检查并行修改，再由主线程构建最终交付包。

独立验证产物位于工作区 `.cache/music-recovery-check/`，主线程的常规target、dist、服务和数据库未因本次验证而重启或迁移。
