# 本地删除接口联调

## 本次问题的实际链路

2026-11-10 只读核对线上访问日志：同一作品第一次 DELETE 返回 200，随后的重复删除返回 404。进一步从线上当前 JAR 读取 `WorkController` 字节码，确认旧接口返回的是被删除的 `Work`，而非新版的 `{deleted:true}`。

原先前端的严格响应校验拒绝这个旧响应，因此删除成功后没有关闭弹窗和移除卡片。用户再次点击同一作品，就看到“作品不存在或你无权访问”。另有带生成尝试记录的歌曲仍会在旧后端触发物理删除外键异常。

本机 5173 原来只把 system 和 quick-creations 发至 8080，其余作品请求仍走线上。单独重启 IDEA 不会改变浏览器代理目标。

## 修正

- 新前端接受新版确认对象，也接受字段完整且 id 与请求一致的旧版 Work 响应。空对象、其他作品、任意 success 字段都不当作成功。
- 遇到明确的 WORK_NOT_FOUND/404 后，以当前身份重新读取列表。卡片确已不在本页时刷新展示；仍在列表或刷新失败则保留错误，不把所有 404 假装成删除成功。
- `scripts/preview-work-routing.mjs` 将预览页的作品集合、library 和单作品元数据接口发送到 8080，并加诊断响应头 `X-QF-Preview-API: local-work`。音频、封面等嵌套路径保留线上代理，避免本机缺少存量媒体文件。`start-preview.ps1` 自动加入该规则。
- 本机新版软删除在同一事务将该作品的 `share_link.active` 置为 false，保证线上旧分享实现仍运行时，原令牌也会失效。保留任务、尝试、媒体和账务记录。
