# 日常运行统一线上主库

用户已确认：日常页面、登录及真实业务使用 `cheerfulmusic.com` 的生产数据库 `qingfeng_music`，不再使用独立支付测试库。正常操作会修改同一套线上数据。

## 启停入口

使用 PowerShell 7：

```powershell
.\scripts\start-local.ps1 -Dev
# 与 .\scripts\start-main.ps1 相同
.\scripts\stop-local.ps1
# 与 .\scripts\stop-main.ps1 相同
```

主库入口固定为 `http://127.0.0.1:5173`。本机 `8080` 提供与线上同版的认证及会话服务，通过 SSH 在 `127.0.0.1:13306` 连接服务器本机 MySQL `3306`；业务与媒体请求由本地前端通过 HTTPS 代理到线上后端，两者使用同一生产数据库及会话记录。不向公网开放数据库端口。

启动入口管理隧道、Java 与前端三个进程，停止时仅操作记录中 PID 和启动时间均匹配的进程。旧 `config/local.properties` 已备份并停用隐式旧库连接；不要用旧的未上线源码或 IDE 入口绕过主库版本清单启动。

启动材料位于忽略提交的 `.secrets/production-main.local.properties`、`.secrets/production-main.manifest.json`、`.secrets/production-main.gateway.json` 和 `.cache/runtime/production-main/`。私有配置不输出到日志或提交到 Git。线上业务接口的内测通行证仅保存在服务端私有文件，不向浏览器下发；用户身份仍由真实登录会话校验。启动时按需刷新过期通行证。

## 版本与数据边界

- 使用已上线同版本 JAR，以及目录树与该线上提交一致的干净 main 前端。原工作区未提交修改保留，但不会把未上线的后端包直接连到主库运行。
- 本地关闭 Flyway 与 SQL 初始化，不在启动时执行尚未上线的数据库迁移。后端版本更新仍遵循项目日常上线、备份与验证流程，再同步本地运行包及版本清单。
- 音乐和封面后台调度仅由线上实例执行；本地保留真实业务的手动调用能力。
- 本地模拟支付、Sandbox 及尚未上线的真实支付功能不向主库写入测试订单或积分。支付正式开放仍以生产版本及真实支付结果为准。
- 自动化测试使用自身临时环境，不得把测试夹具、清库或模拟付款成功数据指向主库。
- 本地维护脚本不再对生产连接执行备份恢复、清理或数据库重建。主库维护使用服务器备份与上线流程。

## 媒体与旧库

日常业务及媒体接口直接使用线上后端，旧 `local:` 音频与封面也由线上读取，不再下载或维护整套媒体副本；新媒体继续使用线上 OSS。

原 `3307/qingfeng_music_codex`、Docker `3308/3309` 的数据库与历史订单不自动删除，也不直接把其中的测试积分、身份或支付订单导入生产。独立支付数据库准备脚本已停用。
