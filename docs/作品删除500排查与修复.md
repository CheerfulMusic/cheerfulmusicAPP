# 作品删除 500 排查与修复

2026-11-10 通过 SSH 只读查询实际业务服务日志及生产库结构。没有执行生产删除、数据库迁移、服务重启或发布。

## 已确认原因

本机 5173 使用工作区新版前端，但 `/api/app/` 仍代理至 `https://cheerfulmusic.com`。线上当前后端执行 `WorkMapper.deleteGenerationTasks` 的 `DELETE FROM generation_task WHERE work_id=?`，被 `generation_attempt.task_id -> generation_task.id` 外键 `fk_attempt_task` 拒绝，返回 500。不是浏览器缓存问题。

只读检查时，截图歌曲“水漫过门槛”仍有 1 个生成任务、6 条生成尝试、2 条音频记录和 2 条分享记录；这些数量仅代表当次检查结果，不代表 OSS 文件逐一校验。

## 修复方式与迁移兼容

使用本地已有的软删除实现：在事务内核对身份、锁定作品、检查已完成歌曲的删除确认，只更新 `music_work.deleted_at`，保留任务、生成尝试、媒体和账务关联。列表、作品访问、音频和公开分享通过未删除作品条件拒绝访问。重复删除保持幂等，不为已提交任务自动退款。

线上 Flyway V26 已是 `hot_song_engagement`，其原始 SQL 从当前运行 JAR 只读提取，Flyway CRC32 为 `217027247`。生产库尚无 `music_work.deleted_at`。因此保留线上 V26 原文，将本地尚未发布的软删除和一键创作迁移顺延为 V27、V28，避免重复版本或校验和冲突。未执行 `repair`，没有修改已应用迁移。

迁移文件重命名后需要 `mvn clean verify`，否则 `target/classes` 中旧的 V26/V27 资源可能残留，造成重复迁移版本。

## 验证与生效边界

新增删除 HTTP 回归场景使用 H2 内存库、离线音乐提供方和随机本机端口：真实创建任务与音频，确认生成尝试存在，先复现物理删除的外键失败，再验证确认提示、CSRF、软删除成功、重复删除、列表移除、任务记录保留和分享失效。自动化不向主库写测试夹具。

本次前端 297 项测试、类型检查和构建通过；后端先清理旧迁移资源，再执行完整 `mvn verify` 通过：共 450 项，411 项通过、39 项按环境条件跳过。跳过项包含专用 MySQL 验证，本次删除回归使用 H2 MySQL 兼容模式，未把它描述为真实 MySQL 删除验证。

右上角入口改为“继续创作一首歌”。这项前端修改通过本地开发服务器即可看到。

删除修复必须在获准发布后，先备份生产版本与数据库、核对同事分支和迁移、发布匹配后端后才能生效。当前本地预览仍使用生产业务接口，因此源码测试通过或合入本地 main，并不能让运行中的旧删除接口自动修复。禁止只把代理改向尚未应用迁移的新 JAR。
