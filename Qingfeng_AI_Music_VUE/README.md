# 青风音乐 Vue 前端

当前正式界面采用Cheerful Music深黑/深灰和橙红主题，按用户ToC定位使用顶部品牌导航、送歌场景、音乐试听及手机菜单。全站运行状态提示和后台式常驻侧栏已移除。Logo、礼物封面、作品卡片与单例播放器共享品牌组件及色彩变量。旧浅色原型保留于上级ui-prototype。

```powershell
cd E:\qingfeng_AI_music\Qingfeng_AI_Music_VUE
npm run dev
```

访问 http://127.0.0.1:5173 ，开发代理默认转发到后端8080。配合后端run-mysql.ps1使用真实草稿服务。

## 已实现

- 正式首页、场景入口、封面切换、筛选、器乐样曲播放。图片明确为AI场景图。
- 中英双语：页头中／EN切换，记住本机选择；导航、创作、作品详情、收礼、找回、播放器及提示均可切换。首页中文标题为“把你的故事，唱给重要的人。”。
- 三步创作表单，MySQL草稿创建、更新、载入和版本冲突提示。
- 称呼、场景与音乐风格采用输入框加推荐标签，提供16／18／24个示例，默认展示8项并可展开；支持自定义输入、中英文和手机排版，选标签不提交表单，保存后可恢复。
- 我的作品分页与继续编辑，保存后刷新从服务端恢复。
- 作品详情：手动歌词另存新版本与确认、MP3/WAV上传、授权试听下载。
- DeepSeek按已保存故事编写中英文歌词，生成后保留为未确认的新版本，支持编辑、另存和确认；请求去重，错误不自动重试模型。
- “继续制作音乐礼物”先保存最新故事再生成歌词并打开编辑页；详情页可重新生成，保留历史版本，刷新不自动再次调用模型。
- 主动创建7天礼物链接、复制/打开、撤销全部分享，收礼人免登录访问。
- 礼物页使用品牌封面、祝福、歌词和播放入口，导入音频与AI生成来源明确区分。
- 可信匿名会话初始化与CSRF请求头，界面不提供虚假登录。
- 未保存离开提示、手机菜单、桌面与手机布局。
- 找回作品页面、一次性找回码下载/复制和跨浏览器恢复。
- 持久化任务状态轮询、待核对说明、只重试音频保存入口。
- 音乐生成弹窗：唱片与音波动效、真实排队／创作／保存阶段、成功与失败状态、后台继续与重新查看；任务进行中点击入口只显示进度，不再次提交。支持中英文、手机、键盘关闭与减少动画设置。
- 播放缓冲、文件失效提示、重试、同作品音频切换和关闭后释放连接。

AI歌词和歌曲生成由后端能力接口控制，本机私有配置已按用户要求开启DeepSeek写词和KIE Suno歌曲适配，点击对应按钮才调用模型。真实模型生成尚未付费实测，浏览器交互使用模拟结果验证。用户也可手动填写歌词、导入已有音频；样曲不作为故事生成结果。草稿保存在当前浏览器对应的创建者名下，清理Cookie可能无法找回匿名作品。礼物链接是持有即可访问的凭据，不要发给无关人员。

## 结构

app组织路由/布局/样式；modules按home/studio/works/gift/identity分业务；shared提供UI、HTTP、全站播放器；platform预留Web与原生桥。Native/App暂缓，Capacitor预备配置保留。

主题入口为app/styles/theme-base.css、home.css、workspace.css、work-detail.css、consumer.css及i18n.css；BrandLogo/NavIcon位于shared/ui，品牌图形在public/brand，默认封面在public/media。旧prototype-base.css/premium.css不再由正式入口导入。视觉说明见上级docs/UI设计更新.md。

语言资源集中在shared/i18n/en.ts，中文源文案作为键，shared/i18n/index.ts提供响应式翻译、日期格式和封面选择。默认中文，通过localStorage的qingfeng.locale保存偏好；浏览器禁止存储时仍能在当前页面切换。仅翻译界面和内置试听示例，用户填写的姓名、标题、故事、祝福和歌词保持原文，表单场景与风格保持原业务值。切换不跳转路由、不重建表单、不打断播放。无需额外翻译API或费用。

公开系统能力查询位于shared/http/system.ts；跨业务使用公开index.ts接口。业务接口类型保留各自模块，Vue模板自动转义用户内容，不使用v-html渲染故事。

### 原生 API 会话

CapacitorHttp 已启用，Android/iOS 的 fetch（包括 FormData 上传）使用原生 HTTP 栈与 Cookie 存储。原生 API 请求携带 include 凭据，网页保留 same-origin。构建前配置可信 HTTPS 的 VITE_API_BASE_URL，随后执行 cap sync 更新原生配置并重新安装 App；仅更新网页资源不会更新原生插件配置。不需要为此放开后端任意来源的 CORS 或降低网页 Cookie 策略。设备验收应覆盖首次会话、登录、受保护接口、音频上传和退出后的会话失效。
参考：https://capacitorjs.com/docs/apis/http
